# ko-tone

어조와 문장이 품질을 좌우하는 한국어 글을 자연스럽게 다듬는 스킬이다. 문장과 어조의 판단은 공개 글쓰기 지침(국립국어원, Microsoft, 토스)과 글쓰기 서적에서 공통으로 권하는 원칙에 기댄다. 원칙 전체와 출처는 `references/style-principles.md`에 있다.

## 적용하지 않는 경우

- 결과물이 한국어가 아닌 작업(영어 글 교정, 한국어를 다른 언어로 번역)은 이 스킬 없이 평소대로 한다.
- 공지, 주간 보고, 회의록, 장애 보고, 릴리스 노트, PR 설명, README처럼 형식이 핵심인 문서를 정리하는 일은 이 스킬 없이 평소대로 한다. 사용자가 그런 문서에 ko-tone을 직접 지정했다면 구성은 건드리지 말고 문장만 다듬는다.

## 기본 태도

1. **더 나은 글이 목표다.** 짧게 줄이는 것이 목표가 아니다. 고친 글이 원문보다 밋밋해지면 실패이고, 원문보다 길어지면 그만한 이유가 있어야 한다. 같은 정보는 한 번만 쓰고, 빈 자리 표시는 남기지 않는다(이메일의 받는 사람 이름과 서명만 예외).
2. **결론부터 쓴다.** 첫 문단에 결론이나 용건, 독자가 할 일을 둔다. 에러 메시지는 무슨 일인지 → 왜(필요할 때만) → 지금 할 수 있는 일 순서로 쓴다.
3. **글 종류의 흐름을 따른다.** 블로그, 이메일, 번역 글은 문단으로 이어 쓰고, 항목 서너 개짜리 나열은 목록으로 쪼개지 말고 한 문장으로 잇는다. 글 종류별 관행은 `references/contexts.md`에서 해당 절을 읽는다.
4. **빈말은 원문에 있어도 걷어낸다.** 근거 없는 평가, 전망, 홍보 문구는 지켜야 할 주장이 아니다. 맺음이 필요한 글(블로그, 회고, 메일)은 빈 결론을 원문의 사실에 근거한 판단이나 다음 단계로 바꾸고(추정이면 추정이라고 쓴다), 짧은 메시지는 내용이 끝나면 끝낸다.
5. **원래 사실은 지킨다.** 수치, 날짜, 이름, 버전, 주소, 링크, 코드, 인용은 본문에서 바꾸지 않는다. 확정, 추정, 계획의 구분과 주장의 강도도 원문대로 둔다. 명백한 오타나 공식 명칭과 다른 표기는 바로잡고 '바꾼 점'에 적는다. 원문끼리 맞지 않거나(예: 날짜와 요일) 위험한 단언이 있으면 본문에서 짐작으로 고치지 말고 '확인해 주세요'에 적는다.
6. **짐작으로 채운 곳은 밝힌다.** 원문이 모호해서 구체화했다면 '확인해 주세요'에 적는다. 수치, 사례, 사용자 반응은 짐작으로 만들지 않는다.

## 한국어에서 특히 볼 것

- **높임 수준:** 원문이 주로 쓴 수준이 상황에 맞으면 그것으로 통일한다. 합쇼체 글 속 "~해 주세요" 요청은 자연스럽다. 제품 화면 문구는 해요체가 기본이다.
- **번역투와 돌려 말하기:** "검토를 진행했다" → "검토했다", "회의를 가졌다" → "회의했다", "개선이 이루어졌다" → "개선했다". 이중 피동("되어지다"), "~에 있어서", 행위자가 분명한 "~에 의해", 사람처럼 말하는 무생물 주어도 고친다.
- **조사와 표기:** 영문·숫자 뒤 조사는 발음에 맞춘다("API를", "EIP-4337을"). 한 글 안에서 띄어쓰기, 문장부호, 용어 표기를 하나로 맞춘다.
- **과잉 교정:** 조사와 어미를 깎은 전보체, 인과가 끊긴 짧은 문장 나열은 AI 티만큼 어색하다.
- 대표 패턴과 고친 예는 `references/patterns.md`에 있다. 판단이 애매하면(높임 수준, 피동을 둘지, 약어 병기 순서, 용어를 풀지) `references/style-principles.md`의 해당 원칙과 '갈리는 지점'을 본다.

## 작업 순서

1. **글 종류를 정한다.** 누가 읽는 어떤 글인지 정하고 `references/contexts.md`의 해당 절만 읽는다.
2. **고쳐 쓴다.** '기본 태도'와 '한국어에서 특히 볼 것'을 적용한다. 원고 파일을 고쳐 달라는 요청이면 고치기 전에 원문 사본을 시스템 임시 폴더에 저장한다.
3. **읽어 본다.** 보통 속도로 소리 내어 읽었을 때 걸리는 문장이 없는지, 첫 문단에서 핵심이 보이는지, 같은 정보가 두 번 나오지 않는지 본다.
4. **필요할 때만 스크립트로 확인한다.** Python 3.9 이상이 필요하고, 명령의 `python3`은 Windows에서 `py -3`로 바꾼다. 코드를 실행할 수 없으면 같은 항목을 직접 확인한다.
   - 원문에 수치, 링크, 코드가 많으면: `python3 scripts/ko_tone_compare.py <원문 파일> <고친 글 파일>`로 바뀐 값을 찾는다.
   - 날짜에 요일을 붙이거나 시간대를 바꾸거나 증감률을 쓸 때: `python3 scripts/ko_tone_facts.py weekday|tz|pct ...`로 계산한다. 머리로 계산하지 않는다.
   - 컨트랙트 주소가 있으면: `python3 scripts/ko_tone_facts.py addr <주소>`로 EIP-55 체크섬을 확인한다.
   - 긴 원고는 `python3 scripts/ko_tone_lint.py <파일>`로 남은 상투 표현 후보를 찾을 수 있다.

## 결과 형식

1. **고친 글 전문.** 그대로 복사해 쓰기 좋은 형태로 준다.
2. **바꾼 점.** 핵심만 3~5개.
3. **확인해 주세요.** 짐작으로 구체화한 곳, 틀려 보이는 사실, 위험한 단언, 원문에 없어 뺀 정보가 있을 때만 쓴다. 주소 체크섬 경고는 맨 위에 둔다.

사용자가 결과만 원하면 고친 글만 준다. 원고 파일을 고쳐 달라고 했으면 파일을 고치고, 파일을 고칠지 분명하지 않으면 대화로만 낸다.

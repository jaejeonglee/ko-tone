# 글 종류별 질문

SKILL.md 3절 끝에 적힌 종류의 글이면 그 종류의 줄만 읽는다. 칸 목록이 아니라 질문이다. 답이 원문에 있을 때만 제목, 첫 문단, 이름 붙은 항목에 드러낸다. 답이 원문에 없으면 칸을 만들지 않고, 빈칸을 넣으려고 새 줄이나 항목을 만들지 않는다. 조직 양식, 공문서 규정, 법정 기재 사항이 있으면 그것이 먼저다. 온점 날짜, '붙임', '끝.' 같은 공문서 표기는 공문서일 때만 쓴다.

## 훑어보는 글: 독자가 찾는 답

| 종류 | 독자가 찾는 답 | 특히 볼 것 |
| --- | --- | --- |
| 공지·안내문 | 나한테 해당하나 / 언제부터 언제까지 / 무엇이 바뀌나 / 내 할 일과 기한 / 예외 / 어디에 묻나(원문에 있으면) | 제목에 무엇과 일시. 일부만 해당하면 대상을 지목 |
| 보고 | 지금 상태 / 계획 대비 / 결정하거나 도울 것 / 다음 계획 | 못 끝낸 일과 사유를 끝에 숨기지 않기 |
| 회의록 | 정해진 것 / 안 정해진 것과 다음 시점 / 누가 언제까지 무엇을 | 할 일은 결정과 겹쳐도 따로 모은다. 정하지 않은 담당과 기한은 '미정' |
| 장애·사고 안내 | 무슨 일 / 영향, 내 것은 괜찮은가 / 지금 상태 / 원인이 확정인가 / 지금 할 일 / 다음 소식은 어디서 | 확인된 사실만. 근거 없는 안심 금지. 원인의 확정·추정 구분. 시각은 원문의 시간대 하나로. 대외 안내는 할 일의 대상을 구체적으로, 사과를 지우지 않기 |
| 보도 자료 | 누가 언제 무엇을 / 왜 기삿거리인가 / 누구에게 확인하나 | 인용문을 지어내지 않기. 원문의 담당자와 연락처를 빼지 않기 |
| 제안서 | 무엇을 결정해 달라나 / 비용과 효과 / 위험과 대안 | 요청을 앞에. 없는 수치를 만들지 않기 |
| 릴리스 노트 | 나한테 달라지는 것 / 내가 바꿔야 할 것과 기한 | 깨지는 변경은 앞쪽 한 곳에. 예정은 예정으로 |
| README·PR 설명 | 무엇이 바뀌나 / 왜 / 어떻게 확인하나 / 리뷰어가 볼 곳 | 원문에 없는 리뷰 포인트를 지어내지 않기 |

## 종류별로 어기면 손해인 것

어기면 글쓴이나 독자가 손해를 본다. 고친 글을 다시 읽을 때(SKILL.md 5절) 묻는다.

| 종류 | 물을 것 |
| --- | --- |
| 자기소개서·지원서 | 원문에 없는 경험, 성과, 수치를 만들지 않았나? 문항과 글자 수를 지켰나? |
| 후기·협찬 글 | 대가를 받았다는 표시가 제목이나 첫 부분에 있나? 원문에 있던 표시를 빼거나 뒤로 옮기지 않았나? 써 보지 않은 경험을 더하지 않았나? |
| 상품 설명 | 근거 없는 최상급, 효능, 보장을 더하지 않았나? 가격, 규격 같은 조건이 원문에 있으면 바로 보이나? |
| 사과문 | 조건부 사과나 뭉뚱그린 대상으로 바꾸지 않았나? 사실 관계, 보상, 재발 방지 약속은 원문에 있는 것만 썼나? |
| 고객 응대 답변 | 정책, 보상, 처리 기한을 만들지 않았나? |
| 채용 공고 | 필수와 우대가 나뉘었나? 근무 시간, 급여 같은 조건이 원문에 있으면 바로 보이나? |

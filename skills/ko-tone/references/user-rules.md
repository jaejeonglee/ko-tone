# 사용자 규칙

사용자의 글쓰기 선호를 규칙으로 쌓아 다음 글부터 적용한다. 이 스킬의 기본 지시는 출발점이다. 규칙은 이 스킬 폴더의 `scripts/ko_tone_rules.py`로 관리한다. 규칙 파일은 스킬 폴더 밖(~/.config/ko-tone, Windows는 %APPDATA%\ko-tone, KO_TONE_HOME으로 바꿀 수 있음, 팀 규칙은 저장소의 .ko-tone)에 있어서 스킬을 업데이트해도 남는다. 아래 명령은 이 스크립트의 하위 명령이고, `path`는 저장 위치를 보여 준다. 명령은 사용자가 작업 중인 폴더에서 `python3 <스킬 폴더>/scripts/ko_tone_rules.py <하위 명령>`으로 실행한다(팀 규칙을 그 저장소에서 찾는다). Windows는 `python3` 대신 `py -3`을 쓴다.

## 우선순위

원문 사실 대조(SKILL.md 2절) > 사용자 규칙 > 이 스킬의 나머지 지시와 평소 판단. 구성이나 순서에 관한 규칙("우리 팀 주간 보고는 이 순서로")도 평소 판단보다 먼저다. 규칙대로 쓰면 이 글에서 어색해질 때도 규칙대로 쓰고 '확인해 주세요'에 그 점을 적는다. keep 규칙에 걸린 표현은 SKILL.md 2절의 표기 교정에서도 고치지 않는다. 단언 낮추기와 부딪치면 고치지 않고 맨 위에 알린다.

## 읽기

`list [--scope <범위>]`로 활성 규칙을 읽는다. 대화나 프로젝트 지침에 붙여 넣은 목록도 활성 규칙이다. 범위는 사용자가 말한 글 종류다. 한국어 이름도 받으며, 표에 없는 이름은 그대로 자유 꼬리표가 된다. 범위를 붙이지 않은 규칙은 모든 글에 적용된다.

| 범위 | 한국어 이름 |
| --- | --- |
| email | 메일·이메일 |
| chat | 메신저·슬랙 |
| blog | 블로그·회고 |
| translation | 번역 |
| talk | 발표 |
| sns | SNS·커뮤니티 |
| intro | 소개 |
| ui | 화면 문구 |
| notice | 공지·안내문 |
| report | 보고 |
| minutes | 회의록 |
| release | 릴리스 노트 |
| doc | 개발 문서 |
| letter | 자기소개서·지원서 |
| reply | 고객 응대 |

## 저장

결과를 본 사용자가 다른 글에도 해당하는 선호를 말하면 이번 글에 바로 반영하고 저장한다. 이 글의 내용만 바꾸는 요청("둘째 문단 빼줘")은 저장하지 않는다.

- 쓰지 말 표현: `add avoid "<표현>" --suggest "<대신 쓸 표현>" [--scope <범위>]`
- 고치지 말 표현(팀 용어, 슬로건): `add keep "<표현>"`
- 그 밖의 선호(높임 수준, 길이, 구성): `add style "<한 문장 규칙>" [--scope <범위>]`
- `--scope`는 사용자가 글 종류를 말했을 때만 붙인다("메신저에서는"). 말하지 않았으면 빼서 모든 글에 적용한다.
- 표현은 다른 글에서도 찾을 수 있게 짧게 적는다. `--example`은 한 문장으로, 이름·주소·수치를 빼고 적는다. `--note`는 목록에 함께 보일 짧은 설명이다.
- 같은 표현이 avoid와 keep에 함께 있으면 add가 알려 준다. 어느 쪽인지 사용자에게 묻는다.

## 승격

처음 받은 선호는 후보로 저장되고, 같은 선호를 한 번 더 받으면 활성이 된다. 이미 있는 규칙(`list --status all`, 후보 포함)과 같은 선호면 새로 만들지 않고 `hit <id>`로 횟수를 올린다. 사용자가 앞으로도, 항상 그렇게 하라고 하면 `add`나 `hit`에 `--activate`를 붙여 바로 활성으로 둔다. 팀 전체 규칙이라고 하면 `add`에 `--project`를 붙인다.

## 알리기

저장하거나 승격했으면 답의 끝에 한 줄을 덧붙인다. 무엇을 어떤 상태(후보, 활성)로 저장했는지와 활성이 되는 조건을 적는다.

## 검토

규칙을 보여 달라는 요청에는 `list --status all`로 활성·후보·보관 규칙을 보여 주고 후보를 적용할지 묻는다. 한 상태만 보려면 `--status`에 active, candidate, retired를 준다. 요청에 따라 `activate <id>`, `retire <id>`(적용 중지, 보관), `remove <id>`(삭제)를 실행한다.

## 확인

긴 원고에서 활성 규칙을 어겼는지 보려면 `check <고친 글 파일>`을 쓴다. 걸린 곳만 보여 주며, 고칠지는 문맥으로 정한다.

## 파일이 남지 않는 곳

코드를 실행할 수 없거나, 규칙 스크립트가 저장 위치가 대화 뒤에 지워질 수 있다고 알리거나, claude.ai처럼 대화마다 실행 환경이 새로 만들어지는 곳이면 저장 대신 목록으로 이어 간다. 목록은 SKILL.md 6절과 같은 꼴이다.

```
# ko-tone 사용자 규칙
아래 규칙은 ko-tone의 기본 규칙보다 먼저 적용한다. 원문의 수치, 날짜, 이름, 코드는 규칙과 상관없이 바꾸지 않는다.
- [<범위 이름>] <규칙 한 줄> (후보)
```

범위 이름은 위 표의 한국어 이름을 쓰고, 범위가 없으면 모든 글이라고 쓴다. 규칙 한 줄은 avoid면 `'<표현>' 쓰지 않기 → '<대신 쓸 표현>'`, keep이면 `'<표현>'은(는) 고치지 않기`, style이면 규칙 문장이다. 후보가 아니면 (후보)를 뗀다.

- 코드를 돌릴 수 있으면 평소처럼 저장한 뒤 `export --all`로 후보까지 뽑아 보여 준다. 줄 끝의 id와 횟수 주석도 함께 붙여 넣게 한다. 새 대화에서 `list --status all`이 비어 있으면 사용자가 붙여 넣은 목록을 `import -`(파일이면 `import <파일>`)로 되읽는다. 손으로 쓴 목록도 같은 꼴이면 되읽힌다.
- 코드를 실행할 수 없으면 위 꼴로 직접 정리한다. 처음 받은 선호는 이번 글에 적용하고 목록에 (후보)를 붙인다. 같은 말을 다시 듣거나 앞으로도 그렇게 하라는 말을 들으면 (후보)를 뗀 목록을 다시 보여 준다.
- 어느 쪽이든 그 목록을 프로젝트 지침에 붙여 넣으라고 안내한다.
